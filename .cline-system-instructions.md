# System Constraints & Best Practices

## Environment (verified)

- **Platform**: win32 (Windows). Shell is **PowerShell 7 (`pwsh.exe`)** at
  `C:\Program Files\PowerShell\7`.
- **Toolchains on PATH**: node v24.x / npm 11.x, git, flutter & dart
  (`S:\Flutter\flutter\bin`), dotnet, python 3.14 + pip, deno 2.x.

## Available Tools

### Native tools
1. `read_files` — read text/image files; supports one-based line ranges;
   batch multiple files per call.
2. `search_codebase` — regex search across the repo; batch queries per call.
3. `run_commands` — non-interactive shell from workspace root. Blocked for
   state-changing operations while in PLAN MODE.
4. `fetch_web_content` — fetch URLs/docs/API references with an analysis prompt.
5. `ask_question` — clarify ambiguity with 2–5 selectable options.

### Desktop Commander MCP (v0.2.x) — preferred for file work
6. `edit_block` ⭐ — surgical find/replace diff edits. **Default choice for
   modifying existing files** (avoids whole-file rewrites).
7. `write_file` — create new files or rewrite small ones; chunk appends to
   ≤30 lines per call.
8. `read_file` / `read_multiple_files` — text, PDF, Excel, DOCX, images.
9. `list_directory`, `create_directory`, `move_file`, `get_file_info`.
10. `start_search` + `get_more_search_results` + `stop_search` — background
    filename/content searches.
11. `start_process` + `interact_with_process` + `force_terminate` — interactive
    REPLs (Python/Node) for data analysis and validation.
12. `write_pdf`; Excel range edits via `edit_block` with `range`.

## Editing Strategy (efficiency rules)

1. **Prefer `edit_block`** over full-file rewrites for any change to an
   existing file; include minimal unique context around the target lines.
2. Use `write_file` only for new files or complete rewrites; append in ≤30-line
   chunks.
3. Batch independent reads/searches/tool calls together in one turn rather than
   serializing them.
4. Validate results with project linters/tests (`npm run lint`,
   `flutter analyze`, `flutter test`) instead of re-reading whole files.
5. For large refactors, prefer a single transform script executed once over many
   individual edit commands.

## Shell Command Strategy

- `run_commands` executes via PowerShell 7 from the workspace root; sequence
  independent commands with `;`.
- Do not use Unix/Linux utilities such as grep, sed, or awk; use native
  cmdlets (`Get-Content`, `Select-String`, etc.) or the dedicated search tools.
- Treat state-changing commands as approval-worthy; destructive commands
  (diskpart, format, reg, etc.) are blocked at config level.
- Arbitrary JSON APIs are reachable via `Invoke-RestMethod`
  (GET/POST with JSON bodies) when no dedicated tool fits.
